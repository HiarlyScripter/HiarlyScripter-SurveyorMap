### dig-Minimap Architecture

Observed classes:

- `Minimap.Plugin`
- `Minimap.ConfigValues`
- `Minimap.Bindings`
- `Minimap.StateUtils`
- `Minimap.SettingsMenu`
- `Minimap.PlayerNamesUpdatePatch`

Key behavior:

- Plugin lifecycle is simple: `Awake`, `Start`, `Update`, `OnGUI`.
- `Awake` detaches plugin GameObject from parent and applies persistent hide flags.
- Main update path directly runs every frame, no complicated watchdog/coroutine lifecycle.
- Gameplay gate is simple:
  - `SemiFunc.RunIsLevel()`
  - `GameDirector.instance != null`
  - `GameDirector.currentState == 2`
- It finds the native camera by name:
  - `"Dirt Finder Map Camera"`
- It keeps `Map.Instance` active:
  - if `Map.Instance != null && !Map.Instance.Active`, call `Map.Instance.ActiveSet(true)`.
- It mirrors the texture already produced by the native map camera:
  - use `camera.activeTexture`;
  - do not create an owned `RenderTexture`;
  - do not call `camera.Render()`;
  - do not hijack `camera.targetTexture`.
- It draws the minimap directly in `OnGUI`:
  - `GUI.DrawTexture(rect, renderTexture, ScaleMode.StretchToFill, false)`
  - skips drawing if not in level, no texture, or the native map tool/TAB is active.
- It changes camera orthographic size for minimap zoom when TAB is not active.
- It restores default zoom when the local native map tool/TAB is active.
- It uses the native map/player systems rather than rebuilding rooms.
- Spectator support adjusts the native `DirtFinderMapPlayer` transform to observed player/camera position.

Why it works:

- It piggybacks on the real native map pipeline.
- It reads the native camera output instead of re-rendering.
- It does not hide/disable the native map camera.
- It does not replace native geometry with custom UI geometry.
- The TAB map remains owner of the real full map interaction.

### clay-BetterMap Architecture

- `BetterMap.BetterMap`

Observed Harmony patches:

- `EnemyParent.DespawnRPC` postfix
- `LevelGenerator.GenerateDone` postfix
- `PlayerAvatar.ReviveRPC` postfix
- `PlayerAvatar.PlayerDeathRPC` postfix

Key behavior:

- `Awake` binds three booleans:
  - show teammates;
  - show enemies;
  - explore all rooms.
- Enemy markers are event-driven:
  - on enemy spawn, get the `Enemy` from `EnemyParent`;
  - choose the enemy body object, preferring `Enemy.Rigidbody` when present;
  - attach `MapCustom`;
  - set `MapCustom.sprite` and `MapCustom.color`.
- Enemy marker cleanup is event-driven:
  - on enemy despawn, remove the `MapCustom`;
  - if `mapCustomEntity` exists, destroy it too.
- RevealRooms is native:
  - patch `LevelGenerator.GenerateDone`;
  - iterate `RoomVolume`;
  - call `RoomVolume.SetExplored()`.
- Player markers use `MapCustom` on `PlayerAvatar`, with color from `PlayerAvatarVisuals.color`.

Why it works:

- It lets the native `Map` render markers through `MapCustom` and `MapCustomEntity`.
- It uses level-generation and spawn/despawn events instead of constant UI reconstruction.
- It uses `RoomVolume.SetExplored()` instead of drawing fake room rectangles.

## 7. Diagnosis Of Current SurveyorMap Failure

Current file audited:

`C:\Users\Hiarly\.codex\PROJETOS\REPO\HiarlyScripter-SurveyorMap-Exec\src\Core.cs`

The current implementation contains useful lessons but should not be the source of the rebuild.

### What Is Already Aligned With References

- It already knows the native map camera name: `"Dirt Finder Map Camera"`.
- It already has a `NativeMapCaptureProvider` that tries to use `camera.activeTexture`.
- It already calls `Map.Instance.ActiveSet(true)` in the activeTexture path.
- It already contains validation/reporting concepts worth preserving.
- It already uses `SendInput` in validation tooling for TAB automation, which is the correct path.

### What Is Causing The Loop

- Too many lifecycle layers:
  - plugin `Update`;
  - plugin coroutine `RuntimeLoop`;
  - controller `Update`;
  - runtime probe;
  - several watchdog/proof paths.
- Too many gates before showing the HUD:
  - allowed run state;
  - player API ready;
  - local player present;
  - native texture ready;
  - capture gate;
  - visibility gate;
  - inventory gate.
- The code can have a working native texture path but still hide the HUD because any one gate fails.
- Diagnostic proof overlays and production minimap rendering are mixed.
- The code grew from debugging rather than from a minimal native-map mirror.

### What Should Be Discarded

- Custom room overlay as primary RevealRooms behavior.
- `SurveyorRoomMapCache` bounds/collider/renderer reconstruction.
- `SurveyorRoomOverlayGraphic`.
- Cyan proof-of-life map/rectangle visuals as a feature path.
- Owned `RenderTexture` creation and camera manual render fallback.
- `RenderCameraOnce`.
- `HideNativeVisuals`.
- disabling `MapCustom`/`MapCustomEntity` sprite renderers.
- large custom marker overlay projection for enemies as the main enemy solution.
- repeated RuntimeLoop/controller/plugin update duplication.
- runtime probe and proof HUD as production behavior.

### Specific Current Bugs/Risks

- `ApplyRevealRooms(float now)` exists but is not called anywhere in `Core.cs`; RevealRooms native behavior is effectively dead.
- `UpdateRoomMapOverlay` rebuilds rooms from colliders/mesh bounds and projects them into a custom `Graphic`, which is exactly the fake-map path the rebuild should avoid.
- `CenterOnPlayer` pans/scales the HUD content root based on projection. This fights the native map camera model and can create drift or non-native framing.
- Enemy markers are scanned and projected into SurveyorMap UI. BetterMap shows the safer architecture: attach `MapCustom` to real world objects and let the native map follow them.
- Current code still contains old manual render/owned `RenderTexture` code even though comments say the activeTexture path is now preferred.
- Native marker filtering disables `MapCustom`/`MapCustomEntity` SpriteRenderers, which conflicts with the intended enemy marker path.

## 8. Recommended SurveyorMap v2 Architecture

Principle:

Use the native map as the source of truth. SurveyorMap v2 should be a thin HUD mirror plus small native-system hooks.

### Class Layout

Suggested classes:

- `SurveyorMapPlugin`
  - BepInEx entrypoint.
  - Creates config.
  - Applies Harmony patches.
  - Owns one `NativeMinimapHud` instance or draws directly in plugin `OnGUI`.
  - Keeps lifecycle simple.

- `SurveyorMapConfig`
  - Minimal config only.
  - Suggested keys:
    - `EnableMinimap = true`
    - `ToggleKey = M`
    - `Width = 260`
    - `Height = 260`
    - `PosX = 24`
    - `PosY = 120`
    - `Opacity = 0.85`
    - `Zoom = 2.25`
    - `RevealRooms = false` initially
    - `ShowEnemies = false` initially
    - `LogLevel = Info`
    - `DebugValidation = false`

- `NativeMapMirror`
  - Resolves `Map.Instance`.
  - Resolves camera named `"Dirt Finder Map Camera"`.
  - Detects gameplay state.
  - Detects native TAB/map active state.
  - Calls `Map.Instance.ActiveSet(true)` while minimap HUD is enabled in level.
  - Reads `camera.activeTexture`.
  - Sets `camera.orthographicSize` only when TAB is not active.
  - Restores native/default zoom when TAB is active or HUD disabled.
  - Does not own or release any `RenderTexture`.
  - Does not call `camera.Render()`.
  - Does not disable camera or `Map.ActiveParent`.

- `NativeMinimapHud`
  - Prefer direct `OnGUI` drawing for the v2 baseline, like dig-Minimap.
  - Draws bottom-left rectangle:
    - `x = PosX`
    - `y = Screen.height - PosY - Height`
    - width/height from config
  - Uses `GUI.DrawTexture` with the native active texture.
  - Applies opacity through `GUI.color`.
  - Does not draw while native TAB is active.
  - Optional simple border only after baseline PASS.

- `RevealRoomsService`
  - Harmony postfix on `LevelGenerator.GenerateDone`.
  - If config enabled, iterate `RoomVolume` and call `SetExplored()`.
  - Log `exploredNow/total/levelId` once per level.
  - If needed, schedule one delayed retry after level generation, not a permanent spam loop.

- `EnemyMapMarkerService`
  - Harmony postfix on `EnemyParent.SpawnRPC`.
  - Harmony postfix on `EnemyParent.DespawnRPC`.
  - On spawn:
    - if `ShowEnemies` false, no-op;
    - resolve `Enemy`;
    - reject null/dead/despawn/inactive;
    - pick host object: `Enemy.Rigidbody` object if `HasRigidbody`, otherwise enemy object;
    - add `MapCustom` if missing;
    - set an original SurveyorMap-created sprite and red/orange/yellow color by danger tier.
  - On despawn/death/inactive:
    - destroy `MapCustom.mapCustomEntity` if present;
    - destroy `MapCustom`.
  - Add periodic cleanup at a low cadence only as safety, not as the main system.

- `SurveyorMapValidationState`
  - Optional lightweight diagnostic JSON/log state.
  - Keep separate from rendering.
  - Do not draw cyan proof boxes in production.

### Flow

Awake:

1. Set `Instance`, `Log`, config.
2. Detach plugin GameObject and make it persistent.
3. Patch Harmony.
4. Log version, assembly path, and checkpoint.

Update:

1. Handle `M` toggle if no text/chat input is active.
2. Refresh native map state.
3. Keep `Map.Instance.ActiveSet(true)` while in level and HUD enabled.
4. Adjust native map camera zoom if TAB is not active.
5. Store the latest native texture reference.

OnGUI:

1. If not gameplay, return.
2. If HUD disabled, return.
3. If native TAB/map active, return.
4. If no native active texture, return and rate-limit log.
5. Draw the texture in bottom-left.

Harmony:

1. `LevelGenerator.GenerateDone` handles RevealRooms.
2. `EnemyParent.SpawnRPC` and `DespawnRPC` handle enemy MapCustom markers.
3. Optional `PlayerAvatar` patches only if teammate marker work is explicitly required later.

## 13. Risks

- `camera.activeTexture` may be null until `Map.Instance.ActiveSet(true)` has run and the native map camera has rendered.
- Keeping `Map.Instance.Active` true may affect native map/UI unless TAB active state is respected.
- Camera zoom changes must be restored while TAB is active.
- `RoomVolume.SetExplored()` hides room-volume map modules, so visual expectation must be validated against native behavior.
- `MapCustom` markers may create native question/marker visuals; do not disable `MapCustomEntity` renderers globally.
- Enemy lifecycle can differ across host/client; spawn/despawn patches must be local-safe and cleanup tolerant.
- Game API fields are internal/private and can change after updates; verify against local assemblies before implementation.
