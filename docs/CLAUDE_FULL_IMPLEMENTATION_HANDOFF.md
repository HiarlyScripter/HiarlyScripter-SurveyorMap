## 1. Brutal Current Problem Summary

SurveyorMap current `Core.cs` became a Frankenstein.

What went wrong:

- The minimap path drifted into proof overlays and diagnostic scaffolding instead of a simple native map mirror.
- Fake/cyan overlays were useful for "is OnGUI alive?" but are not a real minimap.
- `CenterOnPlayer` pans and zooms the HUD content root, which deforms/crops the native texture and fights the native camera.
- RevealRooms had a false PASS risk: there is a native `ApplyRevealRooms()` method, but it is not called, while the visible room path uses a fake overlay.
- Room drawing by bounds/colliders creates fake geometry and cannot preserve native map details like cuts, holes, real walls, and native room shapes.
- Enemy markers are projected into custom UI instead of using native `MapCustom`, which creates drift and extra lifecycle complexity.
- Validation became too tolerant of old logs or weak visual claims.
- Runtime has too many loops/gates: plugin update, coroutine, controller update, probe, proof HUD, capture gates, visibility gates.

Decision:

Rebuild clean. Treat current `Core.cs` as diagnostic history and a warning label, not the architecture.

## 4. dig-Minimap: What Matters

### Lifecycle

dig-Minimap is simple:

- `Awake`
- `Start`
- `Update`
- `OnGUI`

Important lifecycle decisions:

- Detach the plugin GameObject from its parent in `Awake`.
- Make the plugin persistent across scene transitions.
- Keep main runtime logic in direct `Update` and `OnGUI`.
- Avoid a multi-layer runtime controller/probe/watchdog setup.

### Native Camera

It searches all cameras, including inactive ones, for:

`Dirt Finder Map Camera`

Claude should replicate the behavior:

- cache the camera once found;
- re-resolve if null/destroyed;
- do not create a replacement camera;
- do not disable the native camera.

### Native Texture

The important trick:

Use `camera.activeTexture`.

That is the texture the game already renders for the native map.

Claude must replicate:

- read `camera.activeTexture`;
- draw that texture as the persistent minimap;
- treat null active texture as "not ready yet" and rate-limit logs.

Claude must not:

- create an owned `RenderTexture` for the baseline;
- assign `camera.targetTexture`;
- call `camera.Render()`;
- release a render texture used by the native camera.

### Keeping Native Map Alive

dig-Minimap keeps the real map active:

- if `Map.Instance != null` and `!Map.Instance.Active`, call `Map.Instance.ActiveSet(true)`.

Claude should replicate:

- only during valid gameplay and when the SurveyorMap HUD is enabled;
- do not use this in menu/loading;
- be TAB-aware so native TAB does not regress.

### TAB Handling

dig-Minimap detects the native map tool/TAB active state and does not draw over it.

Claude should replicate:

- detect native map active state through `MapToolController.instance.Active` if available;
- while TAB is active:
  - do not draw the persistent minimap;
  - restore/default the native camera zoom;
  - do not hide or deactivate native objects.

### Drawing

dig-Minimap uses `OnGUI` and `GUI.DrawTexture`.

Claude should implement the SurveyorMap baseline similarly:

- bottom-left by default;
- about 260x260;
- `x = PosX`;
- `y = Screen.height - PosY - Height`;
- opacity through `GUI.color`;
- no cyan proof box as the map;
- optional thin border only if it does not hide native fidelity.

- Calls service cleanup on destroy.

Responsibilities:

- determine valid gameplay state;
- find `Map.Instance`;
- find `"Dirt Finder Map Camera"`;

- keep native map active when appropriate;
- set/restore camera orthographic size safely;

- no `camera.Render()`;

### `RevealRoomsService`

Responsibilities:

### `EnemyMapMarkerService`
